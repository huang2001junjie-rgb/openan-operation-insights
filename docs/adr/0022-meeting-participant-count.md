# ADR-0022：例会「出勤人数」随台账采集，出席人数趋势由前端派生折线

- **状态**：已接受
- **日期**：2026-11-10
- **关联文档**：04 §3.8、03 §4.5、02 §6、05 §10；修订 ADR-0005 的「不含聚合字段」口径

## 背景

运营需要在例会出勤页（`/meetings`）回答一个新问题：**每场 TSC 例会实际到了多少人**。首期统计周期为 2026-08-25 → 2026-11-03（每周二例会，2026-10-06、2026-10-20 无会），共 9 场，实到人数 24 / 25 / 25 / 23 / 22 / 23 / 21 / 24 / 26。

关键约束：

1. **人数 ≠ 矩阵出席格计数**。例会成员只有 8 位列，而实到人数为 21～26 人——差额是**非成员列席者**（观察员、嘉宾等），矩阵里根本没有这些人的列。
2. 台账仍是唯一数据源（ADR-0005 的「Excel 台账 + 转换脚本」链路），运营只愿意在现有 xlsx 里加内容，不接新系统。
3. 这是**全场级的会议元信息**（按场一个数），与 ADR-0005「放弃会议元信息」并不冲突：那条放弃的是时长 / 主持人 / 议程等无法在台账里低成本维护的字段；出勤人数是运营已经在统计、且只差一列就能进台账的数字。

## 决策

1. **台账新增一列「出勤人数」**：表头字面量固定为「出勤人数」，逐行填该场全场实到人数（非负整数），早期例会行可留空。列加在成员列之后，成员列的「追加在末尾」约定不受影响。
2. **`MeetingAttendanceRow` 新增 `participantCount?: number | null`**（缺省 / 未填 = `null`），由 `import-meetings.ts` 解析写入 `data/meetings.json`；**接口侧仍纯透传**，无派生、无聚合。
3. **导入脚本按表头字面量识别该列**：与成员列严格区分——该列**不参与出席判定**；单元格为空 → `null`，非负整数 → 该数，其余值 → 告警并按未填处理（不中止导入）。台账无此列时全部行为 `null`（向后兼容旧台账）。
4. **趋势折线完全由前端派生**（`ParticipantsLineChart`，echarts LineChart）：仅取 `participantCount != null` 的行，横轴 = 日期、纵轴 = 人数，标题固定为运营提供的英文 **"Count of Participants of TSC"**；**平均 / 最大**两个统计值由前端对同一点集现算（平均保留 1 位小数），并以 markLine 画出平均线。
5. **两点口径并列展示、不混用**：矩阵行头的「N/8 出席」是**成员列**的出席计数（ADR-0005 原口径），折线是**全场实到人数**——两者在页面上相邻但各自标注来源，互不推导、互不校验（成员全缺席的行也可以有非零出勤人数，如 10.13 / 10.27 / 11.03 这三场新行）。

## 理由与取舍

| 选项 | 结论 |
| --- | --- |
| 人数来源：矩阵 true 计数 / 台账新列 | **台账新列**。true 计数恒 ≤ 成员数（8），与实到 21～26 人根本不是一回事，凭空造不出列席者 |
| 台账形态：额外一列 / 额外一行 | **额外一列**。台账「每行 = 一场例会」，列与行天然一一对应；额外一行需靠位置顺序约定对应关系，读写两端都易错位 |
| 契约：新端点 / 行上可选字段 | **行上可选字段**。`GET /api/meetings` 仍是唯一读路径，矩阵仍是唯一实体；新端点会把同一份台账劈成两个口径 |
| 未填语义：跳过该场 / `null` 透传 | **`null` 透传**。跳过错 silently 改变「台账原序」的场次数；`null` 让前端明确区分「无数据」与「0 人」 |
| 平均 / 最大：接口返回 / 前端派生 | **前端派生**。与 ADR-0005「聚合一律前端派生」的既有原则一致（个人出席率、每场出席人数同例），接口保持纯透传 |

## 后果

**正面**

- 以最小改动（台账 1 列 + 行上 1 个可选字段）补齐「每场实到人数」视图，采集链路、端口、接口形状零变化。
- 旧台账（无「出勤人数」列）导入结果完全合法：全部行 `participantCount = null`，前端折线呈现空态提示，不报错。

**负面（明知并接受的负债）**

- **`participantCount` 无独立校验来源**：它与同行 `attendance` 的 true 计数可以矛盾（列席者使前者恒 ≥ 后者），系统**不校验**二者关系，以台账数字为准。
- **10.13 / 10.27 / 11.03 三场新增行的成员出席格为空白**：按 ADR-0005「空白 = 缺席」计入分母，会拉低全部成员的个人出席率。这是补录真实出席标记前接受的临时状态；出勤人数折线不受影响（该三场的 `participantCount` 已填）。
- **「出勤人数」是表头字面量约定**：运营改列名（如改成「实到人数」）会让该列退回成员列并触发出席记号告警，属于可发现的显性故障而非静默错误。

**不受影响**

- ADR-0005 的核心决策（无主键矩阵、空白 = 缺席、前端不可重排、纯透传端口）全部保留；本 ADR 仅在其上**追加**一个可选字段。
- 既有 19 场中 6～7 月的早期行无出勤人数，折线自然只从 2026-08-25 起有点，符合运营「从 8.25 开始统计」的要求。
