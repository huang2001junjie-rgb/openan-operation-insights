# ADR-0004：活跃度页排行榜改为按个人统计 GitHub 贡献

- **状态**：已接受
- **日期**：2026-09-21
- **关联文档**：02 §4.1/4.2/4.3、04 §3.7/5.2/5.3.8；修订 ADR-0003 的「不受影响」清单
- **命名说明**：本文保留决策当时的文件名；`contributors.json` 已更名为 `github-accounts.json`，对照见 ADR-0008。

## 背景

社区活跃度页右列原为「组织贡献排行」卡：在组织维度行数据上按所选指标取 Top 8。该卡与左侧环形图（组织贡献分布，ADR-0003）同为组织维度，两处信息高度重叠；而运营侧「**谁在持续投入**」的问题（识别核心贡献者、评估个人贡献度、发现可扶持的独立开发者）在页面上完全没有答案——`data/contributors.json` 已采集个人 GitHub 指标，但没有任何视图消费它。

## 决策

1. **排行卡改为个人维度**：右列卡片由「组织贡献排行」替换为「个人贡献排行」（`ContributorRankCard`），展示头像、真实姓名、所属组织名与指标数值。
2. **统计口径**：沿用 `GithubMetrics` 五项指标，接口默认 `sortBy=commits&order=desc`；卡内提供「合并 PR / 提交数 / Issue / 代码行数」四维切换，默认选中「提交数」，取 **Top 8**，零值条目不进入榜单。
3. **展示范围**：全部有贡献记录的个人（`GET /api/contributor-contributions` 已保证仅返回带 `github` 指标者），**含 `orgId` 为空的独立开发者**（以伪组织 `unattributed` 呈现为「独立开发者」标签）；随页面组织筛选联动。
4. **数据补齐**：以 **full 模式**重跑 GitHub 采集回填个人指标。增量模式以 `lastSyncAt` 为游标且个人指标在既有值上叠加，无法回溯历史，故不适用于首次回填。
5. **组织维度不丢失**：左侧环形图（组织贡献分布）与页面底部组织明细表保持不变，组织视角仍由这两处承载。

## 理由与取舍

| 选项 | 结论 |
| --- | --- |
| 位置：新增独立榜单 / 替换组织排行卡 | **替换**。右列与左列环形图同为组织维度、信息重叠；替换后左右两列分别回答「谁投入最多」与「投入分布在哪些组织」，信息密度更高且不新增页面区块 |
| 排行主体：组织 / 个人 | **个人**。组织维度已有环形图与明细表承载；个人维度此前无任何视图，新增信息量最大，且支持「独立开发者」这一运营关注人群 |
| 呈现方式：ECharts 条形图 / DOM 排行列表 | **DOM 列表**。需求要求展示 GitHub 头像，`RankBarChart` 的 y 轴为纯文本标签且不支持图像，改造成 ECharts rich label 成本高、可维护性差；DOM 列表可精确控制头像降级、组织标签与占比条过渡，复杂度更低 |
| 数据源：复用 `/contributions` 行数据 / 新增个人接口 | **复用已实现的个人接口**。`GET /api/contributor-contributions` 与端口（`ContributorContributionPort`）已就绪，无需改动后端；排名切片放在前端（数据量数十条） |
| 回填方式：增量 / full 重跑 | **full 重跑**。增量以既有指标为基线叠加，历史贡献不会被重新计入；full 重算可一次性得到完整口径 |

## 后果

- **正面**：页面从组织维度扩展到个人维度，「谁在持续投入」有了直接答案；独立开发者可被单独识别与筛选；后端零改动，仅新增一个前端查询与卡片，复用既有 `AsyncState` / `Segmented` / `glass-card` 设计语言。
- **负面**：失去组织维度的排行榜视图（组织排序需回到明细表查看，或后续在明细表中提供排序入口）；个人排行展示真实姓名与 GitHub 头像，涉及个人公开信息展示，需遵循 GitHub 公开数据范围（邮箱等身份信息仅用于内存归属判定、不落盘）。
- **不受影响**：环形图（组织贡献分布）、组织明细表、组织筛选、后端接口契约（新增的是既有接口的消费方）。
- **对 ADR-0003 的修订**：其「不受影响」清单中「排行榜」一条随本决策失效——排行榜不再使用组织维度行数据，改由 `GET /api/contributor-contributions` 驱动；环形图与明细表部分仍然成立。
