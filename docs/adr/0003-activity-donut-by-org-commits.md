# ADR-0003：活跃度环形图改为按组织提交数统计

- **状态**：已接受
- **日期**：2026-09-21
- **关联文档**：02 §4.1/4.2、04 §5.2/5.3.5；修订 ADR-0002 的「不受影响」清单

> **修订（2026-09-29）**：**决策 3**（3% 阈值 + 6 个具名扇区上限 +「其他」中性灰聚合）与**决策 4**中关于列表/着色的表述已由 [ADR-0013](./0013-org-distribution-lists-all-orgs.md) 取代——环形图改为**列出全部参与组织**，不再并入「其他」。决策 1、2（按 `github.commits` 的组织维度统计、复用 `GET /api/contributions`）仍然有效。

## 背景

社区活跃度页的环形图（原「贡献构成」）按**贡献类型**切分扇区：合并 PR、提交、Issue、需求、best-practice 五类数量加总后计算占比。该口径存在两个问题：

1. 类型混合了两种量纲与两个数据源（GitHub 代码协作 + Confluence 文档成果），「合并 PR 数」与「需求数」相加没有明确业务含义，占比解读困难；
2. 各类型数量级悬殊（提交数千 vs 最佳实践数十），扇区严重失衡，视觉信息量低。

运营侧真正关心的是「**哪些公司在共建中投入最多**」，即组织维度的贡献分布。

## 决策

1. **统计口径**：环形图改为按 `github.commits`（提交数）在**组织维度**切分扇区，中心显示提交总量。
2. **数据来源**：复用 `GET /api/contributions`（页面本就请求该接口），不再依赖 `/contributions/summary` 的类型总量。`/contributions/summary` 仍保留，供页头「数据更新于」等聚合信息使用，响应契约不变。
3. **「其他」聚合**：占比低于 **3%** 的组织直接并入「其他」扇区（固定中性灰着色，与具名扇区区分）；**头部组织（第一名）始终保留具名扇区**，避免极端分布下整图只剩「其他」。具名扇区至多 **6 个**（= 主题调色板长度），超出者即使占比达标也并入「其他」，保证配色不循环重复、图例长度可控。
4. **着色与列表**：具名扇区按贡献排名取主题调色板，卡片下方的数值列表同步展示各扇区提交数与占比。

## 理由与取舍

| 选项 | 结论 |
| --- | --- |
| 统计维度：贡献类型 / 组织提交数 | **组织提交数**。类型混合量纲与数据源，占比无业务含义；提交数是单一数据源内的同质指标，且直接回答「谁投入最多」 |
| 聚合规则：固定阈值 3% / 固定 Top N | **固定阈值 3% + 6 个具名扇区上限（= 调色板长度）**。长尾是否入图主要取决于自身占比而非组织总数，语义稳定；上限防止组织数增多后配色循环重复、图例过长 |
| 低占比处理：并入「其他」 / 悬停展开明细 | **并入「其他」**。实现简单、信息密度高；长尾组织的具体数值在排行榜与明细表中均可查看，无需在环形图内展开 |

## 后果

- **正面**：环形图直接回答「公司贡献分布」；扇区数量受 3% 阈值与 6 个上限约束，长尾不再产生细碎扇区；复用既有 `/contributions` 请求，无新增接口与后端改动。
- **负面**：失去「贡献类型构成」视角（如需恢复须另行设计视图）；3% 为经验阈值，数据分布显著变化时可能需要调整。
- **不受影响**：排行榜、明细表、组织筛选、后端全部接口契约。
- **对 ADR-0002 的修订**：其「不受影响」清单中「贡献类型分布环形图（`/contributions/summary`）」一条随本决策失效。
