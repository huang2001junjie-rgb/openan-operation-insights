# ADR-0015：首页版本号展示（前端硬编码 · 标题上方大字）

- 日期：2026-10-26
- 状态：已接受
- 决策者：项目负责人
- 关联：无（纯展示层改动，不影响任何数据契约）

## 背景

运营希望对外呈现的看板带有可识别的版本标记（原始诉求：「首页最上面加上版本号 OpenAN26.12」），便于汇报截图与现场演示时确认当前部署口径。诉求经拷问式评审（grill-with-docs）后由决策者拍板；落地过程中位置与样式经历多轮调整，本文记录**最终形态**并保留演进过程。

## 决策

| # | 问题 | 决策 |
| --- | --- | --- |
| 1 | 版本号放哪里 | **首页标题「社区运营概览」上方**，作为页面正文首行（`PageHeading` 新增可选 `version` 插槽）。**不放全站顶栏 `TopNav`**——初版曾拍板放顶栏品牌区，后被决策者推翻（见下「演进」） |
| 2 | 展示文案 | **「OpenAN 26.12」**（完整口径）。初版曾按「与相邻品牌名去重」简写为「AN 26.12」，被决策者**否决**——版本号是对外标识，必须与原始诉求一字不差，可读性优先于去重 |
| 3 | 数据来源 | **前端硬编码常量** `APP_VERSION`，落在 `apps/web/src/lib/version.ts`，发版时人工更新；不读 `package.json`、不由后端下发 |
| 4 | 展示样式 | **无框大字 + 既有渐变文字工具类**：`text-gradient-brand`（brand-200 → brand-300 → accent-300 的 `bg-clip-text`）、`text-[2rem] sm:text-[2.5rem]`、`font-bold`、`leading-none tracking-tight`。字号（32/40px）刻意大于页面主标题 `h1`（24/28px），满足「字要大」 |

## 演进（四轮收敛，记录以免后人重走）

1. 顶栏小号 `Badge` + 简写「AN 26.12」 → 文案被否决、尺寸被判定「太小」；
2. 顶栏加大尺寸 `Badge`（为此给 `Badge` 新增 `size` 变体）+ 完整文案 → 被判定「不要加框」；
3. 顶栏无框纯文本（`text-[0.9rem] font-semibold text-brand-200`）→ **位置被推翻**：「不放 navbar，放标题之上，字要大」；
4. **最终形态**：首页标题上方 `text-gradient-brand` 大字。第 1–3 轮在 `TopNav.tsx`、`ui/Badge.tsx` 上的改动**全部回滚**，`git diff` 确认这两个文件零净改动。

## 理由

- **版本是部署事实，不是数据**：版本号与后端 JSON 数据无关，放进数据契约（`home.json` 等）会让「改版本」退化成「改数据 + 重跑采集」，得不偿失；硬编码常量让发版动作 = 改一行代码 + 重新构建，路径最短。
- **回到原始诉求的字面位置**：诉求原文是「**首页**最上面」，放首页标题上方比放全站顶栏更贴合；首页也是汇报截图的默认页面，其余页面的截图需求弱。
- **无框大字而非徽章**：`Badge` 的边框 + 底色语义是「给某个对象打标签」（组织类型、贡献等级），版本号不是数据标签而是页面级标识；复用既有的 `.text-gradient-brand` 既醒目又不新增样式口径。
- **常量抽到 `lib/version.ts`**：位置从顶栏迁到首页后，常量不应寄居在某个页面组件内；独立文件保证「发版只改一处」，将来任何页面要复用都从同一处取。

## 后果

**受影响面**：

- 新增 `apps/web/src/lib/version.ts`：导出 `APP_VERSION`。
- `apps/web/src/components/layout/PageHeading.tsx`：新增可选 `version?: string`，渲染在 eyebrow 之上。**未传时 DOM 与改动前完全一致**，其余使用该组件的页面零影响。
- `apps/web/src/pages/HomePage.tsx`：传入 `version={APP_VERSION}`。
- `TopNav.tsx` / `ui/Badge.tsx`：**无净改动**（中途改动已回滚）。
- **不变**：所有后端接口、落盘文件与 `schemaVersion`；`package.json` 的 `version` 字段与展示版本号**不联动**（口径独立，展示版以本常量为准）。

**正面**：

- 首页一屏即可辨识版本，汇报与演示截图无需口头说明；
- 改版本成本极低（单点常量），且无数据链路副作用；
- `PageHeading` 的 `version` 插槽可复用到其它页面。

**代价 / 风险**：

- 版本号靠人工维护，存在「发了新版忘改常量」的风险（缓解：`version.ts` 注释与本文档均已写明发版时更新）；
- 展示口径「OpenAN 26.12」与仓库内任何机器可读版本号无关联，自动化工具不应解析它；
- **仅首页可见**：活跃度 / 参展 / 例会 / 身份匹配等页面截图不带版本号。若日后要求全站可见，两条路径：给各页面 `PageHeading` 传 `version`，或改回顶栏（本 ADR 演进第 3 轮的实现可直接复用）；
- 渐变观感依赖 `.text-gradient-brand`（`index.css`），该工具类被调整会连带影响版本号。
