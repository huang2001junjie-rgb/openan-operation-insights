# ADR-0006：身份匹配控制台把「认领目标」与「详情抽屉」拆为两个独立状态

- **状态**：已接受
- **日期**：2026-09-27
- **关联文档**：04 §3.9 / §3.10 / §5.3.10～§5.3.15、README §5 术语表；修订 06 的一条已知问题

## 背景

身份匹配控制台（`/admin/identity`）的自然人模式里，页面把「左栏选中的自然人」同时当作两件事的载体：

1. **认领目标**：候选池每行的「认领」按钮要求先有目标（`ClaimRow` 的 `disabled={!targetPerson}`，提示「请先在左侧选择自然人」）；
2. **详情抽屉的开关**：`PersonDetailDrawer` 的 `open` 直接取自同一个 `selectedPersonId`。

首版把两者接到同一个 state 后，功能在真实操作中**完全不可达**：

- 认领目标存在 ⇔ 详情抽屉打开（根节点 `fixed inset-0 z-50` + 全屏遮罩）⇔ 右侧候选池被遮罩覆盖；
- 遮罩的唯一出口是 `onClose`，而它把 `selectedPersonId` 置回 `null`，认领目标随之消失；
- 于是「已选中目标」与「可点的候选池」永远不能同时成立，「认领」按钮在任何时刻都是 disabled。

`PersonRoster` 里同时存在两个入口——整行按钮与行内「详情」按钮，且两者 `onClick` 完全相同——这本身就是「选中」与「看详情」本应是两个意图的证据，只是被合并到了一个状态上。后端的只读与写接口均正常，问题完全在前端的这一处状态复用。

## 决策

1. **拆成两个 state**：`selectedPersonId`（认领目标，只被左栏行点击写入）与 `detailPersonId`（详情抽屉，只被行内「详情」按钮写入）；`PersonDetailDrawer` 的 `open` 改由后者决定。
2. **行点击 ≠ 打开抽屉**：点行只设认领目标，不再弹出任何遮挡；详情是独立入口。
3. **关闭抽屉不清空认领目标**：选定目标后可在候选池连续认领同一自然人的多个账号。
4. **认领成功后保持选中**：状态不因一次成功认领而复位。
5. **新建即选中**：新建自然人后自动成为认领目标，省去「建完再回列表找一遍」。
6. **「详情」按钮常驻可见**：放弃 hover 才显形的做法。在决策 2 之下它是详情的**唯一**入口，隐藏起来等于让改名 / 调整归属 / 解除认领 / 物理删除无法触达（触屏与非悬停用户尤甚）。
7. **删除与选中解耦但保持一致**：抽屉内物理删除一个人后关闭抽屉；若被删的正是当前认领目标，同时把目标置空，避免目标指向已不存在的自然人。

## 理由与取舍

| 选项 | 结论 |
| --- | --- |
| 选中与详情：共用一个 state / 拆成两个 | **拆成两个**。二者在可用性上互斥（详情是模态遮罩），共用必然导致其一不可达 |
| 行点击行为：选中 + 开抽屉 / 只选中 | **只选中**。行内已有独立的「详情」按钮，两个入口本就有各自的语义，且改动最小 |
| 详情形态：模态抽屉 / 右栏常驻面板 | **保留模态**。不改变既有视觉与信息架构；非模态需把右栏改成三栏，收益不抵成本 |
| 选中生命周期：认领后清空 / 保持 | **保持**。控制台的主要用途是批处理，一次认领后立刻复位会强迫用户反复点选 |
| 目标被筛选隐藏：保持 / 归零 | **保持**。目标只需在「已加载的自然人全集」里可解析即可，被筛掉时按钮依然可用 |
| 「详情」按钮：hover 显形 / 常驻可见 | **常驻可见**。它是唯一入口，不可依赖悬停 |

## 后果

**正面**

- 认领闭环恢复可用：选中目标与操作候选池不再互相排斥。
- 「选中」与「看详情」各自可预期：关抽屉不丢目标，看详情不改变目标。
- 详情入口对触屏与键盘用户可达（按钮常驻可见，行内选中态带 `aria-pressed`）。

**负面（明知并接受的负债）**

- **左栏多了一个持续可见的图标按钮**：行右缘视觉密度上升，且需为它预留内边距，长展示名的可用宽度下降。
- **目标可能"看不见"**：目标若被当前筛选（关键字 / 归属）排除在列表外，行高亮不可见，但候选池顶部仍显示认领目标——需用户自行清空筛选才能看到高亮行。保留此行为是为了避免"改个筛选就把辛苦选定的目标清掉"。
- **新建即选中受筛选影响**：若新建时存在生效的筛选且新人不满足条件，新人不会出现在列表里；目标仍正确，但需清筛选才看得见这一行。

**不受影响**

- 后端接口、`data/*.json` 契约、候选池派生逻辑、组织↔开发者模式的选中语义均不变。
- 既有查询缓存与乐观更新逻辑不变。

## 备注

- 「认领目标」仍是页面级瞬时状态：不落盘、不进 URL，刷新即失效。本次未改变这一点。
- `PersonRoster` 的悬浮工具条原先缺 `pointer-events-none`，不可见时仍会吞掉行右缘的点击；改为常驻可见后该问题一并消失。
